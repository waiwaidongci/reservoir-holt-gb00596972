# 泵房排水试验库容校准

用排水试验的排水量区间校准各档位库容，只发布所有可行解都一致的档位。

澄湾会展园物业水务班组泵房管理 RW-02 雨水回用池。值班员录入空池基准和每次排水前后的档位、排水量范围，系统把跨档试验展开为经过各档的差分约束，叠加库容随液位不降的单调性后求全部可行解；只发布所有可行解都一致的档位，其余标记待补测。无解时给出撤掉后能恢复可行的最少一组试验。主管把算齐的库容表一次性切换发布，机电组在交班页按版本查阅各档库容及采用的试验。

- 排水表只能给出排水量范围，按点值入账会把区间误差误当成精确值。
- 跨档排水同时约束沿途多个档位，手工分摊难以保证各档库容单调不降。
- 试验互相矛盾时，手工台账无法定位是哪几次试验造成无解。
- 补测数据分批到达，中途切换半成品库容表会让交班口径前后不一。

## 业务模块

| 模块 | 用途 |
|---|---|
| 泵房校准总览 | 查阅业务口径、当班流程、校准概况与最新计算。主管可以核对审计记录。 |
| 档位与空池基准 | 维护液位档位排序，录入或更正各档空池基准库容锚点。 |
| 排水试验录入 | 登记排水前后档位与排水量范围，支持整单提交、CSV 导入和停用冲突试验。 |
| 校准解算与诊断 | 发起解算，查看各档确认/待补测状态与可行区间；无解时给出最少冲突组。 |
| 库容表发布 | 仅全部档位确认的计算可发布，单事务内整体切换，旧版本保留可查。 |
| 机电交班报告 | 按版本查看各档库容及采用的试验证据，下载交班 CSV。 |

## 演示流程

1. 在「档位与空池基准」确认 G1–G6 档位和 G1 空池基准 0 m³。
2. 在「排水试验录入」查看 T01–T08 演示试验，其中 T08 与 T03+T04 矛盾。
3. 在「校准解算与诊断」发起首次解算，结果为无可行解，诊断给出最少冲突组 `T08`。
4. 回到录入页停用 `T08`，再次解算，6 个档位全部确认，证据链列出每次采用的试验。
5. 主管在「库容表发布」选择全部确认的计算一次性切换，v1 生效；有待补测的计算无法发布，旧表不会被顶回。
6. 在「机电交班报告」核对各档库容与采用试验，下载交班 CSV。
7. 补测与更正可在同一张单子里提交，整单要么全收、要么整单退回。

## 计算口径

- 档位按液位从低到高排列，变量 V_i 为档位 i 的库容；空池基准给出等式锚点 V_i = b_i。
- 一次从高档 p 排到低档 q 的试验给出区间约束 L_e ≤ V_p − V_q ≤ U_e，跨档试验自动约束沿途各档。
- 结构性约束要求库容随液位不降：V_i ≤ V_{i+1}。
- 全部约束写成差分约束 x_u − x_v ≤ w，用最短路径（Bellman-Ford）求解；出现负环即无可行解。
- 档位 i 在所有可行解中一致，当且仅当其上界（参照点到 i 的最短路）与下界（i 到参照点最短路取负）重合，此时发布该库容；否则标记待补测并给出可行区间。
- 无解时沿负环定位冲突试验，按基数递增搜索撤掉后恢复可行的最少一组试验；只含基准/单调性的结构冲突无法靠撤试验修复。
- 库容表按版本整体切换：只有全部档位确认的计算才能发布，发布在单事务内把新版本置为生效、旧版本整体下线。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放字段配置、解算引擎和演示数据，`routes` 放接口，`models` 放表模型。 |
| 数据 | PostgreSQL 16 存储档位、试验、计算快照与库容表版本。`backend/scripts/seed_demo.py` 可安全重复执行。 |
| 测试 | `backend/tests/test_calibration.py` 为解算引擎规则测试，`backend/tests/test_api.py` 为 API 端到端测试，均可用 `python -I` 运行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、计算状态和档位状态一致。项目许可证见 `LICENSE`。
